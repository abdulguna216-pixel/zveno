# ЗВЕНО — корпоративный сайт

Готовый адаптивный frontend без зависимостей: HTML, CSS, JavaScript, локальные Manrope WOFF2 и 10 уникальных сгенерированных фотографий WebP. Исходное ТЗ сохранено уровнем выше.

## Запуск

Требуется Node.js 22+:

```sh
npm run dev
```

Открыть http://127.0.0.1:4173. Статическую папку `dist` можно разместить на любом HTTPS-хостинге. Для проверки обработчика: `npm test`.

## Приём заявок

По умолчанию форма проверяет поля, но **не отправляет данные** и не сообщает об успешной отправке. Контакты и реквизиты компании не выдуманы. Перед приёмом заявок необходимо:

1. Добавить реальные контакты и реквизиты в футер и диалог политики.
2. Заменить информационный текст политики утверждённым компанией документом с оператором, целями, сроками, получателями и способом отзыва согласия.
3. Подключить HTTPS-обработчик в `dist/config.js`: `leadEndpoint: '/api/leads'` (или внешний HTTPS URL с настроенным CORS), `privacyReady: true`.

### Готовый Node.js → Telegram адаптер

В `server/leads.mjs` есть реальная интеграция. Скопируйте `.env.example` в `.env`, задайте `SITE_ORIGIN`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `PRIVACY_READY=true`, затем:

```sh
node --env-file=.env server/leads.mjs
```

Не храните токен в frontend или Git. На production поставьте HTTPS reverse proxy и ограничение запросов на уровне ingress. Доступность Telegram и допустимость выбранного способа обработки данных должны быть проверены владельцем до включения.

Контракт POST JSON: `{name, phone, company, comment, consent: true, website: ''}`. Успех: HTTP 2xx и `{ok: true}` только после подтверждения доставки. Ошибка: соответствующий HTTP статус и `{ok: false, message}`. Встроены проверка Origin, ограничение размера, серверная валидация, honeypot, базовое ограничение частоты, таймаут. Персональные данные не пишутся в журналы или localStorage.

Размещение в Sites статическое: Node-адаптер остаётся в исходниках, но не запускается на статическом хостинге. Для Sites используйте внешний HTTPS endpoint, возвращающий описанный JSON-контракт. Адрес и статус политики задаются только в `dist/config.js`.

## Содержание и взаимодействия

Пять основных разделов и финальный CTA: услуги, преимущества, этапы, галерея направлений. Название пункта навигации «Кейсы и направления» ведёт к галерее; вымышленные клиентские проекты не представлены. Карточки услуг и направлений заполняют комментарий в заявке. Галерея поддерживает автоматическое движение, паузу, стрелки и сенсорную прокрутку. Есть мобильное меню, клавиатурная навигация, reduced-motion и кастомный курсор только для точного указателя.

Система дизайна и применение обязательного скилла: `docs/DESIGN.md`. Промпты и происхождение изображений: `docs/IMAGE-PROMPTS.md`.

## GitHub и Vercel

Исходники: https://github.com/abdulguna216-pixel/zveno

Production: https://zveno-khaki.vercel.app

Vercel публикует папку `dist` без сборки и установки зависимостей. Настройки зафиксированы в `vercel.json`: Framework — Other, Output Directory — dist, пустые Build Command и Install Command. Корень проекта — корень репозитория.

После подключения репозитория к Vercel изменения ветки `main` автоматически публикуются. Переменные и токены Telegram не включены в репозиторий. Серверный Node.js-адаптер сохранён для отдельного размещения; в текущем статическом деплое приём заявок отключён.

Оригинальное ТЗ: `ZVENO_website_prompt.md`.
